# OSS distribution suite — known failures (#3130, #3136)
#
# What this is: the recorded failure set of `make test-install-oss`, the suite
# that runs internal/policy + internal/analyzer against the tree we actually
# publish (packs/premium/ stripped, per scripts/publish-oss.sh).
#
# Why it is not empty: every entry below is a corpus case that expects BLOCK and
# gets AUDIT in the OSS build. That is a product question — how much of the
# corpus the free tier should detect — tracked in #3136. It is NOT a bug to be
# fixed by relabelling the cases.
#
# Two different things produce a line here, and they are NOT interchangeable:
#
#   1. Blind — no community rule covers the case at all, so the OSS build sees
#      nothing and falls through to the default AUDIT. Most entries are this.
#   2. Tier-split — a community rule DOES fire, at AUDIT, and premium escalates
#      the same pattern to BLOCK plus the attestation receipt. The line is here
#      only because the corpus records the premium-tier decision. These carry a
#      trailing `# tier-split` marker.
#
# The distinction matters because a bare line reads as blindness, and for a
# tier-split case that is the opposite of true. Do not add a tier-split line
# without a test that proves the community rule fires — an unproven claim of
# free-tier coverage is worse than an honest blind spot, since it makes the gap
# invisible in both directions. See TestCommunityTierSeesAgenticRansomware in
# internal/policy/community_tier_visibility_test.go for the pattern (#3161).
#
# Before #3130 this number was zero, because scripts/integration-test-oss.sh
# piped `go test` into `tail` and reported tail's exit status. The gate printed
# "Tests: OK" over all 914 of these for months.
#
# How it is used: scripts/check-oss-baseline.sh diffs a run against this file
# and reports only the delta. A NEW entry means OSS coverage regressed (or a new
# corpus case landed that only premium covers). A FIXED entry means a listed
# case now passes and the line must come out — the file only ever shrinks.
#
# Adding a line is not free: each one is a detection the free tier does not have.
# Removing lines in bulk is the goal (#3136), and when that lands this file is
# expected to empty out and the nightly job becomes a plain gate.
#
# Format: one entry per line, # comments and blanks ignored.
#   case:<subtest path>   a corpus case, deduped across its parent sweeps
#   test:<TestName>       a top-level test with no failing subtests
#
